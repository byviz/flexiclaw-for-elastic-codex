# Elastic ES|QL Assistant

## Purpose

Generate, explain and validate ES|QL for observability investigations while following Elastic tool safety rules.

## When To Use

Use this skill for:

- errors per minute
- top exceptions
- latency percentiles
- logs by service, host or pod
- baseline versus incident comparisons
- throughput drops or spikes
- queries for dashboard panels
- explaining ES|QL results

## Required Workflow

1. Discover indices, streams and fields when unknown.
2. Ask for missing scope only when it cannot be inferred safely.
3. Prefer aggregate queries.
4. Include a time range.
5. Limit row counts.
6. Use `platform_core_generate_esql` to generate queries.
7. Use `platform_core_execute_esql` only for a query generated by Elastic tools or provided verbatim by the user.
8. Explain what each query proves and what it does not prove.

## Natural Flow

Use ES|QL when focused observability tools do not answer the question directly, or when the user explicitly asks for a reproducible query.

For unknown fields, use `observability_get_index_info`, stream schema or index discovery before generating the query.

## Recommended Elastic Tools

- `platform_core_index_explorer`
- `platform_core_list_indices`
- `observability_get_index_info`
- `platform_streams_get_schema`
- `platform_core_generate_esql`
- `platform_core_execute_esql`
- `platform_core_search`

## ES|QL Patterns

Useful investigation patterns:

- count events over time;
- count errors over time;
- top services by error count;
- top transaction names by latency;
- top exception types;
- baseline window versus incident window;
- affected hosts or pods;
- sample events after aggregate selection.

## Safety Rules

- Do not invent field names when schema discovery is available.
- Do not execute a hand-written query with `platform_core_execute_esql`; generate it first unless the user provided it verbatim.
- Do not use unbounded result sets.
- Do not imply a query result proves causation by itself.
- Keep the workflow read-only.

## Output Format

```markdown
## ES|QL goal

## Required fields and indices

## Query

## Why this query is useful

## How to interpret results

## Limitations
```
